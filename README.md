# EQUINORIX Design

Окрема дизайнерська копія EQUINORIX для погодження візуальних покращень. Основа — тестова версія 20, коміт `20a455908513579a36fbec1a140690552653cb74` (`20a4559`). Цей проєкт розвивається окремо від попередньої копії за ТЗ та основного клієнтського сайту.

Окремий репозиторій: [Svip-web/equinorix-design](https://github.com/Svip-web/equinorix-design).

Перегляд на GitHub Pages: [українська версія](https://svip-web.github.io/equinorix-design/uk/).

Репозиторій публічний за прямим дозволом власника; GitHub Pages увімкнено. Збірку й публікацію виконує workflow нижче.

## Дизайн і функції

У цій копії дозволено покращувати композицію секцій, типографіку, відступи, картки, кнопки, іконки та адаптивність. Зміст сайту успадковано з базової версії: дизайнерські зміни не додають нових маркетингових текстів і не скорочують описи послуг.

Візуальні покращення цієї версії:

Поточне оновлення повертає спільну початкову сітку, світліше історичне затемнення та оригінальні кольори й кнопки.

- Перший екран із фото Марбельї на висоту вікна, попереднім світлішим затемненням, білим текстом і початковою синьою овальною кнопкою з білим текстом.
- Компонування шапки повернуто до базової версії 20.
- Усі секції після першого екрана мають білі фони.
- Шість послуг у початковій асиметричній композиції на комп’ютері, з круглою CTA та номерами 01–06. Уточнено відступи й адаптивне розташування на менших екранах.
- Панорамне HR-фото без обрізання та дві білі картки по чотири наявні пункти; на телефоні — одна колонка.
- Окремі колонки історії та відео засновниці з переходом в одну колонку на менших екранах. Плеєр має формат 16:9, прямі кути, без рамки й тіні.
- Видимі підписи полів форми використовують уже наявні назви; головні контактні кнопки ведуть безпосередньо до форми.
- Читабельніші контакти й елементи футера, зрозумілий поточний мовний стан та адаптивне меню.

### Уточнення поточного оновлення

- На початковому екрані логотип і навігація шапки білі; після прокручування на білій закріпленій шапці — темні.
- Відстань від послуг до HR зменшено зі 192 до 96 px на комп’ютері та зі 112 до 56 px на телефоні.
- Зовнішні рамки HR-списків прибрано; внутрішні розділювачі рядків збережено.
- Для WhatsApp використано канонічну іконку Font Awesome розміром 24×24 px; атрибуцію збережено в `ASSET-SOURCES.txt`.
- Додано й перевірено одноразову м’яку появу елементів і легкий паралакс лише HR-фото. Перший екран і шапка не мають reveal-анімації. Обидва ефекти вимикаються за `prefers-reduced-motion`; без JavaScript вміст залишається видимим.

Збережено чотири мовні версії, перемикач мов, закріплену шапку, шість послуг, вісім HR-пунктів, cookies, повернення до форми, відеоблок і WhatsApp. Тексти зберігаються в `content-data.json` та `ui-data.json`; після збірки їх потрібно звіряти з базовою копією.

## Локальний запуск

Потрібен Node.js 20 або новіший. Додаткових npm-залежностей немає.

У PowerShell з каталогу проєкту:

```powershell
npm run build
$env:EQUINORIX_PORT = '4177'
npm start
```

Відкрийте [українську версію](http://127.0.0.1:4177/uk/). Сервер слухає лише `127.0.0.1`; змінна `EQUINORIX_PORT` задає порт цієї окремої копії.

## Перевірки

Залиште сервер запущеним. У другому терміналі з каталогу проєкту:

```powershell
$env:EQUINORIX_PORT = '4177'
npm run check
```

`build` генерує чотири сторінки в `site-copy`. `check` перевіряє синтаксис JavaScript, мовні маршрути, ресурси, кількість послуг, тестовий стан форми й недоступність приватних резервних файлів. Поточне оновлення пройшло 181 автоматичну перевірку та 16 браузерних комбінацій: чотири мови на ширинах 320, 390, 768 і 1440 px. Перевірено кольори шапки, відступи послуги/HR 56/96 px, відсутність зовнішніх рамок HR і переповнення, іконку WhatsApp 24×24 px, одноразову появу та паралакс HR-фото. Код і текстовий зміст форми, мов та налаштувань приватності збережено.

## Підготовка GitHub Pages

```powershell
npm run build:pages
```

Команда спочатку збирає `site-copy`, потім створює лише з її вмісту окремий `pages-dist` із base path `/equinorix-design`. Кореневі HTML-посилання, CSS-ресурси та конкретні JS-шляхи до ресурсів адаптуються до підкаталогу. Текстові дані `page-data.t` та `page-data.u` зберігаються без змін. У цей артефакт не копіюються README, вихідні JSON, переписка, резервні копії чи файли налаштування проєкту.

Workflow `.github/workflows/pages.yml` виконує збірку й розгортання за push у `codex/design-study` або ручним запуском. Він використовує Node.js, наявний в Ubuntu runner, без встановлення npm-залежностей. Результат кожної публікації доступний у вкладці Actions репозиторію.

Збирач додає до URL локальних CSS, JavaScript, медіа та favicon параметр `v` зі значенням `GITHUB_SHA`. Кожен опублікований коміт отримує власні версії ресурсів, щоб браузер запитував оновлені стилі й файли. Для локальної збірки без `GITHUB_SHA` використовується значення `local`.

GitHub Pages обслуговує статичні файли. Режим `preview: true` залишається ввімкненим; серверне надсилання форми цим розгортанням не підключається.

## Що ще не підключено

- `preview: true` вимикає реальне надсилання й збереження заявок. Форма показує стан «Повідомлення не надіслано»; корпоративна пошта та перевірка доставки залишаються окремою роботою.
- Справжніх відеозвернень засновниці ще немає. Поки працює спільне тихе 10-секундне демовідео з фото Марбельї. Воно не є зверненням засновниці; мовні файли підключатимуться окремо.
- Адреса, повні реквізити й затверджені тексти privacy, cookies та legal очікуються. Кнопки документів без наповнення неактивні.
- Реальні URL LinkedIn та Instagram не надані. WhatsApp використовує підтверджений номер.
- Робочі переклади UA/RU та змістові розбіжності наданих EN/ES редакцій потребують остаточного погодження.

### Стан вікна cookies

Короткі назви елементів і дій є в усіх чотирьох мовах. Пояснювальних текстів `cookiesText` та `necessaryText`, а також затверджених тіл документів `policyText`, `cookiePolicyText` і `legalText` немає. Через це п'ять кнопок юридичних документів на кожній мовній сторінці неактивні: три у футері та дві у вікні cookies.

Дії «Лише необхідне», «Прийняти все» та «Зберегти налаштування» наразі зберігають однаковий вибір: `necessary: true`, `analytics: false`. Окремих необов’язкових категорій і аналітики не підключено; наповнення вікна та політик залишається незавершеним.

## Структура проєкту

- `build-local.mjs`, `original-content.mjs` — генерація сторінок.
- `content-data.json`, `ui-data.json` — текстові дані чотирьох мов.
- `site-copy/assets/` — стилі, поведінка інтерфейсу, зображення, шрифти й демовідео.
- `site-copy/assets/config.js` — публічна конфігурація без секретів.
- `server-local.mjs`, `check-local.mjs` — локальний сервер і перевірки.
- `ASSET-SOURCES.txt` — джерела фото, шрифту та іконок.

Приватну переписку, доступи, резервні копії хостингу та попередній звіт не включено до цієї копії. Секрети не можна додавати в HTML, JavaScript, конфігурацію або Git.
